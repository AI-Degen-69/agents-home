# Recommended visual patterns

Pick only the patterns that genuinely improve understanding of this topic.
One pattern used well beats five used decoratively.

- Annotated diagram — label parts of a UI, architecture, or object directly on the picture.
- Flow chart — show a sequence of steps with decisions and branches.
- Architecture map — show components and how data moves between them.
- Timeline — show order of events or version history.
- Comparison table — put before/after or option A vs option B side by side.
- State transitions — show states as nodes and transitions as arrows.
- Before/after — two screenshots or snippets proving a change.
- Chart — bar or line chart only when there are real numbers to compare.
- Callouts — highlighted boxes for warnings, key insights, or uncertainty.
- Concrete example — one realistic end-to-end example beats abstract description.
- Minimal interaction — tabs, toggles, or step-throughs that reveal one idea at a time.

Rules: inline CSS, JavaScript, SVG, and canvas only (no build step, no external
dependency); respect reduced-motion preferences; coherent narrative and clear
visual hierarchy rather than a collection of widgets.
