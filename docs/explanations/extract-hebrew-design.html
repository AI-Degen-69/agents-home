2המקרה שהתגלה עכשיו — זה לא מחרוזת פלט

ב־i-pick-issue המשפט הבעייתי הוא הוראה שמגדירה מחרוזת. ב־v-babysit-pr-and-merge מצאתי משהו אחר לגמרי.

מקרה א׳ — הוראה שמגדירה מחרוזת

// i-pick-issue/SKILL.md, שורה 41 — בתוך פסקה אנגלית
Propose a concrete order of work … Header names the action:
`המשימה המומלצת להתחלה 🎯` with the recommendation as the default.
Never write that an issue was *selected* (`נבחר`) …

זו הוראה, לא דוגמה. היא אומרת לסקיל מה לכתוב. אי אפשר לנתק אותה מהפסקה האנגלית בלי לשבור את המשפט — ואם תישאר במקום, היא תצביע על מחרוזת שאולי כבר לא קיימת.

מקרה ב׳ — עברית שהיא לא תבנית פלט כלל

// v-babysit-pr-and-merge/SKILL.md, שורות 121-125
1. **Issue state:**  `gh issue view … --jq .state` — OPEN = 🔴 (חובה).
2. **Leftover artifacts:** … any hit = 🟡 (מומלץ) …
3. **Git cleanliness:** … non-empty = 🔴 (חובה).
Pick the highest signal: 🔴 > 🟡 > 🟢. All clean = 🟢 (דלג, continue…).
זה חלץ אחר

אלה לא מחרוזות שהסקיל חייב להפיק — הן רמזי סימון בתוך הוראות עבודה. והפאק האנגלי כבר פתר אותן: 

OPEN = 🔴 (Required)   // was (חובה)

כלומר חובה → Required, מומלץ → Recommended, דלג → skip. זו תרגום נקודתי, לא תבנית פלט.

4התוכנית, שלב אחר שלב

הכיוון נכון; סדר הביצוע הוא שקובע אם זה יצליח או יישבר באמצע.

  1. להחליט על שם הקובצים לפני שכותבים שורה שם אחד למקום שמוגדרים בו המחרוזות, ושם אחד לחוזה. שני השמות נחלצים בהחלטה אחת, כי אחרת כל תחנה תתויג אחרת.
  2. לבצע תחנה אחת — i-pick-issue היא הקשה ביותר (הוראה + חוזה + שתי בדיקות שנעלמו). אם היא עובדת, יש דפוס מוכן לתשע האחרות.
  3. לוודא שהמגן חוסם קובץ אחד בלבד המדדה המחייב: אחרי השינוי, sync --check חייב לדווח ש-SKILL.md יכול להסתנכרן — כלומר שאין בו עברית כלל.
  4. רק אז — שאר תשע התחנות העבודה היא חוזרת. מתחילים רק אחרי שהתבנית הוכחה על תחנה אחת.
סדר חשוב במיוחד

לא להתחיל מכל עשר התחנות. אם המבנה שגוי, תשנה עשרה קבצים בטעות במקום אחד — והנזק גדול מהבעיה שניסינו לפתור.

6המנגנון, בשורות

שני מקומות בסנכרון. שניהם כבר קיימים — רק צריך להוסיף אליהם.

א. לא להעתיק את קובץ התבנית

ב־EXCLUDE — המנגנון שכבר מסנן קבצים לפני העתקה:

const EXCLUDE = [
  (rel) => rel.startsWith("evals/snapshots/") || …,
  (rel) => rel === "results.json",
  (rel) => rel === "references/output-template.md",   // חדש
];

ה־gitignore אינו עוזר כאן: הסנכרון מעתיק ישירות מהדיסק ולא דרך git.

ב. למחוק את ההוראה המסומנת

ליד rewrite — שם בדיוק נכנסת הפונקציה:

// Delete blocks marked local-only. One rule for every station.
const LOCAL_BLOCK = /^[ \t]*<!-- local-only:begin -->[\s\S]*?^[ \t]*<!-- local-only:end -->[^\n]*\n?/gm;
const strip = (text) => text.replace(LOCAL_BLOCK, "");
סדר הפעולות קריטי

הסינון חייב לקרות לפני ההשוואה same(src, dest). אחרת הסנכרון יחשוב שהקובץ זהה כשהוא לא — ולא יעדכן אותו מעולם.

7סדר הביצוע

תחנה אחת כהוכחה, ורק אז שאר תשע.

  1. להוסיף את שני הכללים לסנכרון שורה ל־EXCLUDE ופונקציית strip. בלי זה אין תבנית — רק רעיון.
  2. לבצע i-pick-issue בלבד התחנה הקשה ביותר: חוזה, הוראה שמגדירה מחרוזת, ושתי בדיקות עבריות. אם היא עובדת — יש דפוס לתשע.
  3. המדדה המחייב sync --check חייב לדווח ש־SKILL.md נסתנכרן ללא חסימה, ושהמגן חוסם קובץ אחד במקום שניים.
  4. רק אז — שאר תשע התחנות העבודה חוזרת. אם המבנה שגוי, עדיף לגלות אחרי קובץ אחד ולא אחרי עשרה.
