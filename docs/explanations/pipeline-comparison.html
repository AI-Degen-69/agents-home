💡 Key Differences at a Glance

Parallelization Model

Matt Pocock runs implement-spec with multiple AI agents across separate worktrees in parallel, merging to one integration branch — trading sequential simplicity for speed.

Hermes runs build tasks sequentially (single agent per task), but Station I has parallel-safe pick analysis so multiple issues can be worked simultaneously across sessions with file-disjointness checks.

Retrospective Layer

Matt Pocock has a dedicated retro skill (v1.3.1) that post-session improves environment — AGENTS.md navigation, lint rules, coding standards. Finds are classified: mechanical violations → deterministic checks (linters/hooks/CI); judgment calls → CODING_STANDARDS.md.

Hermes has no equivalent skill. Guardrail improvement is fragmented: CONSTRAINTS.md (Station II), NOTICED-BUT-NOT-TOUCHING ledger (Station VI), dead-code removal (Station VI).

PR Review Strategy

Matt Pocock focuses on risk reduction for the reviewer: diagrams instead of prose, before/after evidence, blast radius + rollback feasibility before review.

Hermes focuses on proof before review: browser gate (playwright-cli only), OCR delegation scan, Spec axis (missing/added/impl-wrong), post-review re-verification gate. Heavier on automated verification, lighter on risk visualization.

📋 What Each Could Borrow

🔷

Hermes ← Matt Pocock

  • Parallel build execution — adapt iii-build-plan to optionally spawn subagents on disjoint tasks (parallel frontier), like implement-spec
  • Dedicated retro skill — periodic post-session analysis that classifies findings into deterministic checks vs. CODING_STANDARDS.md
  • Diagram-first PR summaries — Mermaid/file-tree/pseudocode summaries instead of prose-heavy PR bodies
  • Merge danger assessment — blast radius + rollback feasibility in the PR body before review
🟣

Matt Pocock ← Hermes

  • Pipeline-triage gate — check dirty tree / unpushed commits / open PR before starting work
  • Station III-B feedback loop — structured corrections between build and review (not just retro after)
  • Quick-fix fast lane — trivial work bypasses the entire pipeline straight to main
  • Clean Exit Gate — 7-check verification (merge, base sync, no leftover branches, zero open findings) before declaring done
